# Поиск ФИО и организаций в Excel

Весь рабочий код — в `model.ipynb`. Данные — локальные Excel-выгрузки из CRM,
подключения к CRM нет. Метрики выводятся таблицами и графиками matplotlib.

```bash
.venv/bin/python -m jupyterlab model.ipynb
```

Ядро: `Python (serch_pers .venv)`. Зависимости — в `requirements.txt`.

## Работа с Excel

Настройки находятся в разделе 1. Укажите `EXCEL_PATH` и включите `RUN_EXCEL`.
Ячейки выполняйте сверху вниз. Основная работа с Excel — в разделе 8.

| Что сделать | Настройки |
|---|---|
| Проверить текущую модель | `RUN_EXCEL = True` |
| Дообучить | Дополнительно `TRAIN_EXCEL = True` |
| Сравнить параметры | Дополнительно `SEARCH_PARAMS = True` |
| Посчитать финальный test | После выбора модели включить `RUN_TEST` и выполнить только ячейку test |

Для одного обучения используются `EXCEL_LR` и `EXCEL_EPOCHS`. Поиск сравнивает
этот режим, три learning rate и вес ORG 1.5. Для повторов задайте
`TRAIN_SEEDS = [42, 43, 44]`. `SPLIT_SEED` оставляйте прежним.

Выбор модели идёт по validation. Финальный test использует то же разделение
из памяти ноутбука; параметры по нему не подбираются. Результаты поиска остаются
в `excel_results`, `excel_candidates` и `excel_best` до перезапуска ядра.
Сохраняются веса, токенизатор и служебная конфигурация модели в новой папке `runs/excel_…/`.
JSON-отчёты и файлы истории не создаются. Старые результаты в `runs/` сохраняются.

В Excel нужны колонки `Комментарий`, `Статус`, `Разметка JSON`.
Берутся строки со статусом `проверено`. Разметка в ячейке — список сущностей
с `start`, `end`, `label` (`PER`/`ORG`) и `text`; без сущностей — `[]`.
Позиции считаются с нуля, правая граница не включается.
Содержимое комментариев в метриках не выводится.

Прошлые метрики на Excel и Collection3 уже показаны в ноутбуке; для их просмотра
не нужно читать исходные файлы. Collection3 включается отдельно через
`RUN_COLLECTION3`, новое обучение на новостях — через `TRAIN_MODEL`.

Маскировка Excel — раздел 10: укажите входной файл и новое имя результата.
Исходная книга не меняется. Оформление, ссылки и комментарии не переносятся;
формулы заменяются на `[ФОРМУЛА]`.

Проверки кода используют только вымышленные данные:

```bash
.venv/bin/python -m unittest test_crm_training test_crm_checks -q
```
